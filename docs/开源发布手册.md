## 1. 上传 GitHub（按顺序执行）

### 1.1 仓库名已修正（已完成）

主题目录名、Text Domain、数据仓库（`osiera-data`）、代码仓库现在统一是 **osiera**。文本里的地址已同步（`style.css` 的 `Theme URI`、`README.md`、`CHANGELOG.md`、本手册）。旧地址 `osirea` 由 GitHub 301 重定向到新地址，已分享出去的链接不会断。

### 1.2 只提交主题本体：排除 `backup/` 与 `data-init/`

| 目录 | 体积 | 为什么不进仓库 |
|---|---|---|
| `backup/` | 30MB | 本地版本快照（`r100-default-title`、`r118-monitor-gtag` 等），属于开发过程产物 |
| `data-init/` | 7.4MB | 起始内容数据集（46 张演示图 + 1 个 mp4 + JSON），已单独放在 `osiera-data` 仓库 |

`data-init/` 是**可以被排除**的，因为主题不是直接读本地文件：`inc/setup/data-init.php` 里的 `tpi_data_init_fetch()` 会按 `init-config.json` 的 `data_init_url` 远程拉取，本地没有就自动走远端。

代价有两条，接受即可：

- 导入起始内容时**必须联网**，且 `osiera-data` 仓库要保持公开；
- 用户 clone 下来首次导入会比本地少几秒。

排除规则写在 `.gitignore`（阻止克隆带入）和 `.gitattributes`（`export-ignore`，阻止进入 Release zip），两边都配好了。

### 1.3 本地历史已重建，推送不需要 `--force`

远端仓库现有两个占位提交（`Initial commit`、`Simplify Osiera theme description`），本地历史已以 `origin/main` 为父提交重建，所以 `push` 是正常快进，不会出现 `refusing to merge unrelated histories`。

当前状态：`main` 分支 → 1 个本地提交（188 个文件 / 3.4MB）→ remote `https://github.com/Lingyv07/osiera.git` → **尚未推送**。

### 1.4 推送

```bash
cd "D:/App/phpstudy_pro/WWW/127.0.0.2/wp-content/themes/osiera"
git push -u origin main
```

首次会要求认证，两种方式选一：

- **HTTPS + Personal Access Token**：GitHub → Settings → Developer settings → Personal access tokens → 新建，勾 `repo` 权限；推送时用户名填 `Lingyv07`，密码栏粘贴 token。
- **Git Credential Manager 弹窗**：Windows 上装了 Git 会自带，推送时弹浏览器登录即可。

推送完成后 `git log --oneline -3` 应看到自己的导入提交在 `Simplify Osiera theme description` 之上。


### 1.5 打第一个版本

```bash
git tag -a v1.0.0 -m "1.0.0"
git push origin v1.0.0
```

推 tag 后 `.github/workflows/release.yml` 会自动：校验 tag 与 `style.css` 里的 `Version` 一致 → 用 `git archive` 打出 `osiera-1.0.0.zip`（顶层目录自动是 `osiera/`）→ 挂到 Release 上。

这个 zip 就是用户下载安装包，也是将来提交 WP.org 的文件。

## 4. 开源策略

### 4.1 许可证：你现在选的是 GPLv3，它意味着什么

WordPress 核心是 GPLv2+，主题的 PHP 属于衍生作品，**必须是 GPL 兼容许可证**——这不是可选项。你选的 GPLv3 是合规的，WP.org 也接受。但要知道两个差别：

| | GPL-2.0-or-later（生态主流） | GPL-3.0-or-later（你现在用的） |
|---|---|---|
| 与 GPLv2-only 插件组合分发 | ✅ 可以 | ⚠️ 法律上有摩擦 |
| 专利授权条款 | 无明文 | ✅ 明文授予 |
| 反 Tivoization | 无 | ✅ 有 |
| WP.org 接受度 | ✅ | ✅ |
| 社区预期 | 绝大多数 WP 主题用这个 | 少数 |

**结论**：不打算做硬件锁定、也没有专利风险要处理的话，`GPL-2.0-or-later` 是更省事的选择。真要改，只需动 3 处（`style.css` 的 License/License URI、`LICENSE` 文件、`README.md` 的 License 段），`readme.txt` 里也有一处 `License:`。

**不能做双许可**：PHP 部分永远是 GPL；可以商业化的只有品牌、托管服务、Pro 插件/附加模块、支持合同。

### 4.2 四条可选的变现路径

| 模式 | 怎么做 | 风险 |
|---|---|---|
| **纯免费 + 赞助** | GitHub Sponsors / 爱发电，README 挂赞助入口 | 收入极低，适合当作品集 |
| **Freemium（最常用）** | 本仓库保持功能完整 → 另开私有仓库做 Pro 插件（多站点授权、高级模板、表单集成） | 免费版必须"能用"，不能故意阉割，否则 WP.org 直接拒 |
| **主题俱乐部** | 年费订阅，含全部模板 + 支持 | 要持续出模板，断更口碑崩 |
| **定制/交付** | 主题开源当获客，卖建站与二次开发 | 本质是接活，不是产品 |

既然主题已经有询盘入库、SMTP、结构化数据这些"企业站刚需"，最顺的路径是 **Freemium**：GitHub 版完整可用（建立信任）→ 高级能力（多语言深度、批量导入、白标）放 Pro。

### 4.3 提交 WordPress.org 主题目录（可选，但值得）

好处：官方搜索流量、后台一键更新、用户信任。代价：审核严格、周期以周计。硬性条件：

- 100% GPL 兼容，所有捆绑资源（图片、字体、图标）逐一能说清来源；
- `Text Domain` 必须等于 slug `osiera`，目录名也必须是 `osiera`；
- 不允许 trialware / 功能锁：免费版必须完整可用，不能"激活后才解锁首页模块"；
- 不允许自带更新检查器（更新由 WP.org 接管）；
- 不能捆绑或自动安装插件；
- 不能有隐藏的 SEO 链接、不能强制页脚署名（可以给选项，默认关）；
- `readme.txt` 必须存在、格式正确，Screenshot 1200×900；
- 通过 Theme Check 插件扫描，`WP_DEBUG` 下零 notice。

提交入口：`https://wordpress.org/themes/upload/`（上传 Release 里的 zip）。

### 4.4 开源前必须做的安全自查

代码公开 = 漏洞地图公开。你的主题有几处需要重点过一遍：

1. **`api/` 下 4 个 REST 端点**：`get-cookies.php` 用了 `permission_callback => '__return_true'`，公开可调用。至少补 nonce 校验与频率限制，否则可以被刷库。
2. **`api/inquiry.php`**：表单直接写库，检查 nonce、字段长度上限、SQL 是否走 `$wpdb->prepare`。
3. **`tables/smtp.php`**：SMTP 密码存在 options 里且回显到表单，确认 `manage_options` 权限 + nonce；考虑改用 `wp-config.php` 常量或加密存储。
4. **`inc/common/request.php:51`**：`AUTH_KEY` 缺失时回落到 `'your_secret_key_here'`，签名会变成可预测值。公开后这行会被第一时间发现，建议缺失时直接 `wp_die()`。
5. **`u_token` cookie**：`httponly` 为 false（前端要读），确认它不含敏感信息、且服务端不单靠它做鉴权。

对应的披露通道已经写进 `CONTRIBUTING.md`。建议再加一个 `SECURITY.md` 写清响应时限（比如 72 小时内确认）。

### 4.5 版本与发布节奏

- **语义化版本**：`1.0.0` → 修 bug `1.0.1` → 加功能 `1.1.0` → 破坏性改动 `2.0.0`；
- **三处版本号必须同步**：`style.css` 的 `Version`、`readme.txt` 的 `Stable tag`、`CHANGELOG.md` 的最新条目（CI 只校验前两者与 tag）；
- **tag 用 `v` 前缀**：`v1.0.0`，与 `Version: 1.0.0` 对应（工作流就是这么校验的）；
- 节奏建议：功能版一月一次、安全修复随时发。

### 4.6 治理：让仓库看起来"有人管"

- `main` 开分支保护：PR 必须过 CI、禁止直推；
- Issue 用模板（已给），PR 用 `.github/PULL_REQUEST_TEMPLATE.md`（需要的话再加）；
- 把好上手的任务打 `good first issue`，这是外部贡献者的入口；
- 每个 Release 写清"改变了什么 + 升级要不要备份"，别只写 `1.0.1`；
- 品牌：主题名 `Osiera`、Logo、域名值得注册/声明，GPL 只约束代码，不约束名字。别人 fork 后不能继续用你的名字发布。

## 5. 常见坑清单

| 坑 | 现象 | 处理 |
|---|---|---|
| 目录名不是 `osiera` | 后台提示主题破损 / 翻译失效 | 目录名、Text Domain、`Text Domain` 三者必须一致 |
| `style.css` 头部被别的内容顶到非首行 | 主题在后台不显示 | 头注释块必须是文件最前面，前面不能有 BOM、空行、别的注释 |
| 提交了 `backup/` | 仓库凭空多 30MB，历史清不掉 | `.gitignore` 已挡；若已提交，用 `git rm -r --cached backup` 再提交 |
| 忘了 `.gitattributes` 的 `export-ignore` | Release zip 里带 `.github/`、`README.md`，WP.org 审核会提 | 已配置，`git archive` 时自动剔除 |
| 中文文件名进仓库 | Linux 服务器上路径乱码 | 主题内所有文件名用英文小写 + 连字符 |
| Windows 换行符 | 服务器上 CSS/JS 出现多余空行、diff 全红 | `.gitattributes` 的 `eol=lf` 已统一 |
| 用户下载 zip 后解压出双层目录 | 上传报 "主题缺少 style.css" | 工作流用 `--prefix=osiera/`，顶层只有一个 `osiera/` |
